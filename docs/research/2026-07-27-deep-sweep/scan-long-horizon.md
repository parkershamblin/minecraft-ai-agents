## Per-system profiles

**DEPS (arXiv:2302.01560, "Describe, Explain, Plan and Select").** Goals are LLM-generated natural-language sub-goal sequences in Python-like syntax (`mine(obj={'log':3}, tool=None)`); a learned horizon-predictive selector ranks parallel sub-goals by estimated steps-to-completion, and a behavior-cloned goal-conditioned controller executes skills. Split: LLM plans/explains, neural selector+controller execute. Replan trigger: controller fails a sub-goal → descriptor summarizes game state (inventory, biome, GPS) as text → explainer LLM does CoT error localization → both are concatenated into the planner prompt for a revised plan. Codex planner: 48.56% avg over 71 tasks, ObtainDiamond 0.59% in 10 game-minutes (12k steps @20Hz). Key ≤13B datapoint: a **fine-tuned LLaMA2-13B** planner hit crafting-table 90%, wooden-pickaxe 80%, furnace 70%, stone-pickaxe 80% — while pretrained LLaMA2-70B managed only 50-60%. Fine-tuning beat 5× scale.

**GITM (arXiv:2305.17144).** Three-layer LLM hierarchy: Decomposer (goal → sub-goal tree using internet-crawled text knowledge), Planner (structured actions), Interface (handcrafted code executing keyboard/mouse) — so the recipe knowledge and the actuation are essentially code/text-KB, with the LLM (GPT-3.5-class chat model per paper) selecting within them. Planner records successful action lists into text memory for reuse. Results: **67.5% ObtainDiamond** in the 10-min/12k-step protocol, **100% of Overworld tech-tree items** unlocked (first agent to do so), 32 CPU cores, 2 days, no GPU. No Nether/dragon. Caveat: the "structured actions" interface does the heavy lifting — this is the closest published architecture to your fixed-verb mineflayer executor, and it's the pattern that made a small-ish chat model sufficient.

**Plan4MC (arXiv:2303.16563).** LLM used **offline only** to build a skill graph relating RL-trained basic skills (plus a "Finding-skill" for exploration); runtime planning is pure code-side graph search — zero LLM calls in the loop. 40 MineDojo tasks, some needing 10+ sequential skills; tech tree tops out pre-diamond. Proof that once dependencies are a graph, planning needs no LLM at all.

**JARVIS-1 (arXiv:2311.05997).** GPT-4/ChatGPT + MineCLIP planner over `mine/craft/smelt`/navigate primitives, STEVE-1 as low-level controller. Two replan mechanisms: **self-check** (pre-execution simulation of inventory state changes to validate preconditions — rule-checkable, exactly what your ledger does) and **self-explain** on environmental failure. Multimodal memory stores (task, successful plan, observation, symbolic state), retrieved by backward task decomposition + CLIP similarity; grew to 425 successful trajectories over 4 self-improvement epochs. **ObtainDiamondPickaxe 12.5% @60 min** (6.22% @20 min), 200+ tasks. GPT-4 and ChatGPT performed similarly as planner (planning here is shallow selection, not deep reasoning). No Nether.

**STEVE-1 (arXiv:2306.00937) / MineDreamer (arXiv:2403.12037).** Low-level keyboard/mouse controllers, not planners. STEVE-1 = VPT fine-tuned into MineCLIP latent space ($60 compute); robust on 12/13 *short-horizon* early-game tasks only. MineDreamer adds Chain-of-Imagination (diffusion-generated goal images guiding the policy), roughly doubling STEVE-1's instruction-following; still needs an external planner for tech-tree work. Both irrelevant to a trusted-executor stack like yours — they solve the actuation problem you've already solved with mineflayer verbs.

**Cradle (arXiv:2403.03186).** General computer control via screenshots + GPT-4V: six modules (information gathering, self-reflection, task inference, skill curation, action planning, memory); plans are Python skill sequences over raw key/mouse primitives. Evaluated on RDR2 missions (later versions add more games), **game paused during GPT-4V latency**, screenshots every 0.5s. Self-reflection compares before/after frames to detect failure and correct. Entirely frontier-VLM-dependent; the transferable idea is only the module decomposition.

**Optimus-1 (arXiv:2408.03615).** The knowledge-graph answer: **HDKG** encodes craft/mine dependencies as a directed graph queried by code-side topological sort (parameter-free), plus **AMEP** multimodal experience pool (success AND failure trajectories, MineCLIP-filtered frames). A reflector periodically emits COMPLETE/CONTINUE/REPLAN; REPLAN sends the planner back through HDKG retrieval. GPT-4V planner (~$5,000 API), STEVE-1 controller, 3.6k-36k step limits. 67 tasks: wood 98.6%, iron 46.7%, **diamond group 11.6%** (human baseline 17.0%), overall 22.3% vs human 36.4%. Open MLLMs (DeepSeek-VL, InternLM-XComposer2) gained 2-6× from the same memory structures — the graph+memory transfers to weak models even when raw capability doesn't.

**Optimus-2 (arXiv:2502.19902) → Optimus-3 (arXiv:2506.10357).** Optimus-2 trained GOAP, a goal-observation-action policy, on 25k videos / 30M pairs (MGOA). **Optimus-3 is the strongest open-weight full-agent datapoint: Qwen2.5-VL-7B** converted to MoE (1 shared + 5 task experts: planning/perception/grounding/reflection/action; dual task/layer routers), trained on 293k samples for ~$300 API + 36h on 4×L40. Planning accuracy 94% (vs Optimus-2 79%), **diamond-group long-horizon 15%** (vs 13% O-2, 11% O-1/GPT-4V), 60% on open-ended tasks. A trained 7B beats a prompted GPT-4V agent across the board — but via serious SFT+RL pipeline, and evaluation ran on 8×L40. No Nether/dragon tasks.

**ADAM (arXiv:2410.22194, ICLR 2025).** Learns the tech tree as a **causal graph from scratch via interventions** (interaction module documents action→outcome), planner+actor+memory then plan over the learned graph; MLLM perception; mineflayer; GPT-4-turbo in reference code. Claims near-perfect causal graph where baselines carry ≥30% edge error, significant diamond/iron speedups (unquantified in sources I could reach), and — uniquely — **keeps working in modified Minecraft with altered recipes**, because knowledge is discovered, not prompted. The LLM load is light (perception + hypothesis proposal); graph learning and planning are code-side.

**Odyssey (arXiv:2407.15325, IJCAI-25).** The most direct existence proof for your stack. **MineMA = LoRA fine-tune of LLaMA-3-8B/70B on 390k Minecraft-Wiki QA pairs**; agent = 40 primitive + 183 compositional mineflayer skills (Voyager-derived, text-only, no vision). The skill library alone obtains **diamond 21.7% @5min → 92.5% @10min → 100% @15min** (120 trials) — long-horizon reliability lives in the composed skills, not the LLM. MineMA-8B beats Voyager+GPT-4o-mini on most single-round combat-planning tasks (e.g., 1-zombie 8/8 vs 3/3 but faster iters) and multi-round replanning (LLM critic sees inventory deltas + battle outcomes, self-validates sub-goals post-action) cuts completion time ~3-4× over three rounds. Autonomous exploration: Odyssey+MineMA-8B ~37 distinct items @80 iterations, beating DEPS/ReAct/AutoGPT/Voyager with GPT-4o-mini. No Nether/dragon tasks anywhere in the benchmark.

**PSN — Evolving Programmatic Skill Networks (arXiv:2601.03509, Jan 2026).** Evolves a network of code skills with online structural refactoring on failure (mineflayer); progresses the tech tree faster and with lower variance than Voyager, which stalls at the diamond stage. Successor to the Voyager/Odyssey skill-library line.

## Explicit answers

**1. Goal representation / code-LLM split.** Every system that progresses deep into the tech tree at small scale moves planning **out** of the LLM: Plan4MC (graph search, LLM offline), GITM (text KB + sub-goal tree), Optimus-1 (topological sort over HDKG), ADAM (learned causal graph), Odyssey (composed skills encode the how). Free-form LLM planning (DEPS, Voyager) tops out at 0.59% ObtainDiamond or requires GPT-4. For your fixed-verb stack: encode craft/smelt/tool dependencies as a code-side DAG the deliberation prompt can only *select from* — this is the field's convergent answer.

**2. Replan mechanics.** Universal trigger: sub-goal failure detected by state check (not LLM judgment). Context given to replanner: current inventory/biome/position summary + failure explanation (DEPS), inventory deltas + outcome across rounds (Odyssey multi-round, which measurably improves an 8B), COMPLETE/CONTINUE/REPLAN verdict from experience retrieval (Optimus-1). JARVIS-1 adds *pre*-execution precondition checking. Your abandon-and-repropose streak mechanism is precisely DEPS's explainer loop done rule-based — the literature says add the *state-delta summary* to the repropose prompt.

**3. Milestone SOTA.** Table above. **No agent of any kind has a published autonomous dragon kill from a fresh survival world**; the milestone market resolved NO in January 2026. Nether-and-beyond is essentially unbenchmarked — even the 2025-2026 agents (Optimus-3, PSN) stop at diamond-tier. A villager collective that entered the Nether reliably would be past published SOTA.

**4. ≤13B numbers.** DEPS LLaMA2-13B fine-tune: 70-90% on early tech tree. Odyssey MineMA-8B (LoRA LLaMA-3-8B): beats GPT-4o-mini-Voyager on combat planning, 37 distinct items exploring, diamond via skills 92.5%@10min. Optimus-3 (Qwen2.5-VL-7B MoE, trained): diamond group 15%, planning 94%. Optimus-1's open-MLLM ablation: memory structures give 2-6× to weak models. Consistent story: **8B + structure ≥ frontier + free-form**.

**5. Cross-episode memory formats that worked.** (a) JARVIS-1: (task, plan, state, outcome) tuples retrieved by task decomposition — text-only variant fits pgvector directly; (b) GITM: plain text lists of successful action sequences per sub-goal (cheapest, proven); (c) Optimus-1 HDKG: static dependency graph, no learning needed — *ship it as code*; (d) AMEP-style storing failures alongside successes is what made Optimus-1's reflector work; your ledger already captures both — the missing piece is retrieval of "last time we tried X, plan Y succeeded" into the deliberation prompt.
